## Authoritative UTCP compatibility requirements

### Legacy v0.1 constructs must be removed

UTCP v1.0 changed core and plugins into separate packages, changed client construction from `UtcpClient()` to asynchronous `UtcpClient.create()`, made registration/calls asynchronous, and made transport plugins explicit. Old single-package or synchronous implementations are legacy. ([v0.1-to-v1.0 migration, breaking changes](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/migration-v0.1-to-v1.0.md#L11-L67))

Configuration and manual renames are breaking schema boundaries:

- Config `providers` became `manual_call_templates`.
- `provider_type` became `call_template_type`.
- Tool `parameters` became `inputs`.
- Tool `provider` became `tool_call_template`.
- Variable-loader configuration moved to `load_variables_from`.

These names come directly from current migration examples and issue guidance. Any repository still producing or parsing former keys needs migration or an explicit legacy adapter. ([configuration migration](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/migration-v0.1-to-v1.0.md#L69-L104), [manual migration](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/migration-v0.1-to-v1.0.md#L106-L179), [common migration issues](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/migration-v0.1-to-v1.0.md#L358-L398))

Transport support is plugin-owned. TypeScript code must install and side-effect import each used `@utcp/*` transport before client creation; importing only `@utcp/code-mode` is insufficient for MCP, HTTP, text, file, or CLI manuals. ([Code Mode direct-use guidance](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/README.md#L176-L209), [MCP bridge imports](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/index.ts#L1-L33))

### v1.1 protocol allowlisting is mandatory for mixed manuals

Every call template may define `allowed_communication_protocols`. Missing or empty value restricts registered and callable tools to manual's own `call_template_type`. An HTTP manual containing CLI or MCP tools therefore loses those tools unless list explicitly permits `cli` or `mcp`. This is both registration-time filtering and call-time enforcement. ([migration behavior table](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/migration-v1.0-to-v1.1.md#L15-L109), [CallTemplate API](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/api/core/utcp/data/call_template.md#L10-L39), [client enforcement API](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/api/core/utcp/implementations/utcp_client_implementation.md#L25-L57))

Manual call-template names may contain letters, numbers, and underscores; special characters should be replaced with underscores. Code Mode additionally sanitizes discovered UTCP names for TypeScript interfaces. Repositories should preserve original UTCP names for lookup while exposing sanitized interface names, exactly as upstream bridge does. ([CallTemplate name contract](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/api/core/utcp/data/call_template.md#L10-L39), [bridge name mapping](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/index.ts#L59-L103))

Current manual model requires `utcp_version`, `manual_version`, and a tool list. Current tool model exposes `name`, `description`, `inputs`, `outputs`, `tags`, optional `average_response_size`, and `tool_call_template`. Consumers should validate at boundary with installed SDK serializers instead of maintaining partial hand-written interfaces. ([UtcpManual API](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/api/core/utcp/data/utcp_manual.md#L10-L49), [Tool API](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/api/core/utcp/data/tool.md#L62-L106))

### Specification prose contains a version-value conflict

Current v1.1 provider quick-start examples declare `utcp_version: "1.0.1"`, while current v0.1-to-v1.0 migration's “v1.0” example declares `utcp_version: "0.2.0"`. Both are present on same default branch. Therefore no modernization should rewrite manual version values solely from prose examples; actual SDK serializer validation plus known-good fixture tests must decide accepted values until upstream clarifies contradiction. ([provider example](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/for-tool-providers.md#L19-L70), [migration example](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/migration-v0.1-to-v1.0.md#L106-L179))

## Current Code Mode implementation contract

### TypeScript engine `1.2.12`

`callToolChain(code, timeout = 30000, memoryLimit = 128)` runs user code inside `isolated-vm`. User code becomes async-function body, so top-level `await` and `return` work. Resolved value crosses isolate boundary through callback `Reference` objects; host races result against timeout and always disposes isolate. Older forks that use synchronous IIFE result transfer miss upstream async-result fix. ([current implementation](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/typescript-library/src/code_mode_utcp_client.ts#L170-L275), [fix commit](https://github.com/universal-tool-calling-protocol/code-mode/commit/cb87dd40d1951de6846f3b7fac0f56f814c2d967))

Runtime interface helpers remain TypeScript-specific `__interfaces` and `__getToolInterface`; registered tools are exposed through sanitized `manual.tool` namespaces. Python intentionally differs: leading-underscore helpers were replaced by `interfaces` and `get_tool_interface` because RestrictedPython rejects leading-underscore names. Cross-language wrappers must not force one helper spelling onto both runtimes. ([TypeScript helpers](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/typescript-library/src/code_mode_utcp_client.ts#L15-L59), [Python helpers](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/python-library/src/utcp_code_mode/code_mode_utcp_client.py#L58-L106), [Python rename commit](https://github.com/universal-tool-calling-protocol/code-mode/commit/dd5777d0fb6bf7f293b143a40d10aeadda2a9dab))

### MCP bridge `1.2.1`

Upstream MCP surface is one prompt (`utcp_codemode_usage`) and seven tools: `register_manual`, `deregister_manual`, `search_tools`, `list_tools`, `get_required_keys_for_tool`, `tools_info`, and `call_tool_chain`. `tools_info` accepts multiple names. Implementations with singular `tool_info`, missing batch lookup, or renamed keys are not wire-compatible with current bridge. ([prompt and registration tools](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/index.ts#L105-L167), [discovery tools](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/index.ts#L169-L278), [execution tool](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/index.ts#L280-L336))

Four inspection tools advertise `readOnlyHint: true`, `openWorldHint: false`, and `idempotentHint: true`: `search_tools`, `list_tools`, `get_required_keys_for_tool`, and `tools_info`. Registration, deregistration, and arbitrary execution do not claim read-only behavior. ([current annotations](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/index.ts#L169-L278), [annotation change commit](https://github.com/universal-tool-calling-protocol/code-mode/commit/80dab39986d89b241c22ff56da35beab46fe6f37))

`call_tool_chain` accepts `code`, timeout default `30000` ms, and output-size default `200000` characters. It preserves MCP content blocks, appends a text block containing non-MCP results and logs, truncates oversized text, and returns MCP `isError: true` on exceptions. Implementations returning only raw JSON discard current MCP content semantics. ([bridge execution result handling](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/index.ts#L280-L336))

Stdio cleanliness is a functional requirement: upstream redirects `console.log` and `console.warn` to stderr before connecting `StdioServerTransport`. Config lookup uses `UTCP_CONFIG_FILE`, then working-directory `.utcp_config.json`, then packaged fallback. Local servers should preserve those launch and output contracts unless they deliberately document a replacement. ([stdio setup and output routing](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/index.ts#L35-L57), [config lookup](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/index.ts#L340-L380))

### CLI default-branch contract

Shell CLI provides `prompt`, `search`, `list`, `info`, `keys`, `run`, `login`, and `validate`. Commands reserve stdout for JSON (NDJSON for login) and route diagnostics to stderr. It loads explicit `--config`, then cwd `.utcp_config.json`, then `UTCP_CONFIG_FILE`. ([CLI command contract](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-cli/index.ts#L1-L81), [help and dispatch](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-cli/index.ts#L160-L365), [config order](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-cli/src/config.ts#L24-L75))

CLI source includes `oauth2_user` authorization-code/device-code handling and writes acquired token to dotenv, but `oauth2_user` does not appear in current UTCP specification auth API, which lists `api_key`, `basic`, and `oauth2`. Treat interactive OAuth as Code Mode CLI/package capability, not normative UTCP v1.1 schema, until specification catches up. ([CLI OAuth contract](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-cli/index.ts#L145-L153), [CLI OAuth implementation](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-cli/src/oauth.ts#L1-L30), [specification auth API index](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/api/index.md#L17-L45))

Fix downstream metadata to actual source rather than copying fields. ([MCP manifest](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/package.json#L33-L42))

## Concrete update requirements for affected repositories

Use following as plan inputs, not automatic edits:

1. **Classify runtime.** Shell-capable Codex, Claude Code, Cursor, or Cowork integrations should evaluate released CLI `0.1.1`; MCP-only clients should stay on bridge `1.2.1`. Preserve bespoke MCP bridge only where it adds reviewed behavior not available upstream. ([upstream host guidance](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/README.md#L125-L174))
2. **Establish released dependency floor.** TypeScript engine `1.2.12`, MCP bridge `1.2.1`, Python `1.1.0`, UTCP JavaScript core at least `1.1.x`, Node `>=18`, Python `>=3.10`, `isolated-vm ^6`. Keep unreleased CLI `0.1.2` separate. ([TypeScript manifest](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/typescript-library/package.json#L38-L69), [MCP manifest](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/code-mode-mcp/package.json#L43-L65), [Python manifest](https://github.com/universal-tool-calling-protocol/code-mode/blob/04fba67b1aab632def1c8b321bf9fae851579ceb/python-library/pyproject.toml#L5-L26))
3. **Migrate schema.** Remove v0.1 `providers`, `provider_type`, `parameters`, and `provider`. Produce `manual_call_templates`, `call_template_type`, `inputs`, `outputs`, and `tool_call_template`; load variables via supported loaders. Validate configs/manuals with installed SDK serializer. ([UTCP migration guide](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/migration-v0.1-to-v1.0.md#L69-L179))
4. **Audit mixed protocols.** For every manual, compare discovery transport with every returned tool's `call_template_type`. Add minimum necessary `allowed_communication_protocols`; test both registration filtering and call-time rejection. ([v1.1 guide](https://github.com/universal-tool-calling-protocol/utcp-specification/blob/262fd4b4b2a93a224711d27c929aa594ad974f78/docs/migration-v1.0-to-v1.1.md#L15-L109))
5. **Load plugins explicitly.** Install and import only transports each runtime needs, before `CodeModeUtcpClient.create()`. Flag CLI plugin as high risk because it can execute local commands; keep manual sources trusted and allowlists narrow.
